## 三、判準：什麼叫對得上

先寫死，看到結果不准改。

| 等級 | 條件 | 結論 |
|---|---|---|
| ✅ **通過** | 進場時間吻合 ≥ 98%（≥196/200）**且** 總損益差 ≤ 3% | 兩個實作量到同一件事 |
| ⚠️ **要查** | 吻合 90–98%，或總損益差 3–10% | 逐筆比對，原因要寫進這份文件 |
| ❌ **不通過** | 吻合 < 90%，或總損益差 > 10% | 其中一個實作有錯，先找出來再談別的 |

**方向不一致必須是 0 筆。** v4 只做多，出現任何一筆空單就是設定沒對上。

## 四、已知會造成差異的六個原因（先列出來，免得事後亂猜）

1. **進場時點。** Python 用確認根收盤 `C[i]`；Pine 的
   `process_orders_on_close = false` 用**下一根開盤**。M15 上這個差異很小
   （延遲測試顯示延後 1 根 t 由 +2.03 → +2.26），但**逐筆價格一定對不上**。
   → 看的是**筆數與時間吻合度**，不是進場價完全相同。
2. **資料源不同。** 我的 M15 來自你匯出的 CSV；TradingView 用的是即時 feed。
   同一根 K 線的 OHLC 可能差幾分錢，足以讓邊界訊號（剛好卡在
   `bufATR` 或 ATR 0.10% 門檻上）一邊有、一邊沒有。**預期少數幾筆進出。**
3. **ATR 起算點。** `ta.atr(14)` 用 RMA，序列從圖表第一根起算；
   Python 從 CSV 第一根起算。若兩邊的起點不同，前 50–100 根的 ATR 會有殘差。
4. **Properties 分頁蓋掉腳本。** 初始資金 / 訂單大小 / 佣金 / 槓桿都以
   Properties 為準。跑之前逐格確認（見 Pine 檔頭）。
5. **佣金換算。** Pine 是 `cash_per_contract = 2.0`，TradingView 內部
   1 盎司 = 0.1 合約 → US$0.40 來回。Python 直接扣 US$0.40。應該一致，
   但如果 TradingView 的每筆手續費不是 HK$3.12 附近，這一條就是元兇。
6. **時區。** CSV 的時戳與 TradingView 圖表時區若不同，進場時間會整體平移。
   → 若吻合度接近 0 但筆數接近，先查這一條，不要查別的。

## 五、⚠️ 對得上**不代表規則有效**

這是 README §21 栽過的地方，寫在這裡免得重犯：

> 當時我用 2022-09 之後的 707 筆定稿，年化 +7.24%、P(>0) 97%，
> 並以「兩個獨立實作對到 1% 以內」佐證。**那是錯用的：
> 兩個實作測的是同一段期間，確認的是量測穩健，不是規則有效。**
> 樣本外 2018–2022 跑出 −HK$1,768、PF 0.839。

這次對數能證明的只有一件事：**Pine 和 Python 在同一段資料上算出同一件事。**

規則有沒有效，唯一的證據仍然是樣本外，而樣本外目前是：
只做多 −HK$739（t = −0.98）；只做多＋波動門檻 **+HK$169（t = +0.46，51 筆）**。
**由虧轉平，不是轉贏。**
