## 三、例行流程

1. **數據進來**：使用者電腦上的 `futu/push_to_gcp.py`（v15）每分鐘把 HK.HSI_FRONT 的 K_1M 推到 GCS `futu_k_1m`（歸檔 `archive/futu_k_1m/HK.HSI_FRONT/<日期>.json`），MT5 另推 NAS100（`US.NQ_FRONT`，5 分 K，紐約時間）。
2. **Cloud Run 推進**（服務 `zhuge-risk-manager`，europe-west1）：每次推送觸發 `dizai_update`，依序更新 variants → 衡 → 缺 → 突破V；每根 K 線一個狀態機，狀態存各自 GCS 檔。日誌每分鐘一行「⛰️ [地載陣] HK.HSI_FRONT 推進 1 根 1 分 K」。
3. **VHSI**：`dizai_vhsi_history`＝repo 的 `canary/data_external/vhsi_daily.csv`（raw GitHub，GCS `dizai/vhsi_daily.json` 快取 6 小時）加富途 HK.800125 近期；突破V 和缺的過濾用。
4. **Telegram**：訊息寫進各狀態檔的 `st["notices"]`；`dizai_heng_flush` 在 Cloud Run 設有 `TG_BOT_TOKEN`／`TG_CHAT_ID` 時直接發送；沒設時由 GitHub Action `hsi-peak-signal` 經 `?view=futu_range&report=signals` 拉取並以 id 前綴確認（`heng:`／`que:`／`tupo:`／`dz:`）。落後最新 K 線超過 60 分鐘的通知標記為過期不發。通知用「落單格式」（方向、張數、市價或掛單價、止賺、止蝕、下次加倉價），開頭 `【地載陣・衡】`、`【地載陣・缺】`、`【地載陣・穩60】`、`【地載陣・進NQ】`。
5. **網頁**：`?view=dizai`（公開，`&format=json`）；地載・合在頁頂；交易時段每 60 秒用 JS 重載（列印中不重載）。頁面有「🖨️ 列印成 PDF」。`?view=strategies`（🧭 策略總表）列出各策略現時持倉方向並偵測衝突。**改這兩頁請保留** `PRINT_CSS`、`print_toolbar_html`、JS 重載寫法，以及總指揮的「💼 富途實倉」區塊。
6. **偏離監控**：每週日 03:37 HKT 的 `screener_scorecard.yml` 抓上述狀態檔，累積到 `research/divergence/dizai_trades.json`，對 `research/divergence/expectations.json` 的 `dizai_*` 7 筆（PR #114）算燈號。目前 7 行都是 ⚪（無成交）；起算日 2026-10-10，第一個完整月燈號最早 **2027-04**。穩60 的「任何止蝕都算偏離」不會自動判，要看 `DIVERGENCE.md` 詳情的虧損筆數。若你改了 `trades` 欄位名或起算日，要通知 SOP 顧問。
